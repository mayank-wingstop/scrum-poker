# F-002 — Participant Join Flow

## Context

Once a facilitator has created a session (F-001), they share the session URL with team members. This feature delivers the join flow: a participant who navigates to `/session/:sessionId` sees a name-entry screen, submits their display name, and is placed into the live session via WebSocket. The server broadcasts the new participant to everyone already in the room.

If the session does not exist (invalid or expired ID), the participant sees a clear error message rather than a broken UI.

---

## Goals

1. Render a "Join session" screen when a participant navigates to `/session/:sessionId` and has no existing identity in `sessionStorage` for that session.
2. Validate the display name (1–30 characters, non-empty) before connecting.
3. Open a WebSocket connection to the server and send a `JOIN` message with `{ sessionId, name }`.
4. On a successful `SESSION_STATE` response, transition the participant into the voting room view.
5. Store the participant's assigned `participantId` in `sessionStorage` so identity can be restored on refresh.
6. Handle the case where a participant reconnects to a session they previously joined (restore identity from `sessionStorage`, skip the name screen, reconnect automatically).
7. Show a clear error state if the session ID does not exist on the server.

---

## Non-Goals

- Authentication or persistent accounts.
- Facilitator join flow (facilitator is placed in the room by F-001 directly).
- Kicking a participant (F-001 facilitator controls — future).
- Spectator mode (all participants in MVP can vote).

---

## User Stories

**US-002-A — Participant joins via shared link**
> As a team member, when I open the session link I want to see a name entry screen so I can introduce myself before entering the room.

**US-002-B — Participant validates name**
> As a team member, I want to see a validation message if I try to join with an empty or too-long name so I know what to fix.

**US-002-C — Participant enters the room**
> As a team member, after submitting my name I want to be placed immediately into the voting room so I can start estimating.

**US-002-D — Participant rejoins after refresh**
> As a team member, if I accidentally refresh the page I want to be automatically reconnected to the session without having to re-enter my name.

**US-002-E — Participant sees error for invalid session**
> As a team member, if the session link is no longer valid I want to see a helpful error message rather than a broken page.

---

## Constraints

- WebSocket `JOIN` message must be sent after the WS connection is `open`, not before.
- The server must respond with `SESSION_STATE` on a successful join or `ERROR` on failure.
- Participant ID is assigned by the server (UUID v4) and returned in the `SESSION_STATE` payload.
- `sessionStorage` key: `participantId-{sessionId}` (scoped per session so multiple tabs work independently).
- Reconnection attempt uses exponential backoff: 1 s, 2 s, 4 s, cap at 8 s (per `specs/ARCHITECTURE.MD`).
- Display name: 1–30 characters.
- The join screen must be mobile-responsive and keyboard accessible (WCAG 2.1 AA).

---

## WebSocket Flow

```
Client                        Server
  |                              |
  |--- WS open ----------------->|
  |--- JOIN { sessionId, name } ->|
  |                              |--- validate session + name
  |<-- SESSION_STATE ------------|  (includes participantId)
  |                              |
  |    [on invalid session]      |
  |<-- ERROR { message } --------|
```

---

## Success Criteria

- Navigating to `/session/:sessionId` (no existing identity) shows a centered "Join session" form with a name input and a "Join" button.
- Submitting a valid name opens a WebSocket connection and sends a `JOIN` message.
- On receiving `SESSION_STATE`, the participant is shown the voting room (F-003 layout).
- `sessionStorage` stores the `participantId` keyed to the session ID.
- Refreshing the page reconnects automatically without showing the name form again.
- Navigating to a non-existent session ID shows an error message "Session not found" with a link back to the home page.
- An empty name submission shows an inline validation error and does not attempt to open a WebSocket connection.
- The "Join" button is disabled while the WebSocket is connecting.
- All existing tests pass; new tests cover the `JOIN` WS handler (server) and the `JoinSession` component (client).
- Coverage thresholds from `specs/TESTING.MD` maintained.
