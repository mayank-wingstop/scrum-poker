# F-007 — Invite Players Panel

## Context

Once a facilitator creates a session, they need an easy way to share the session link with teammates. Currently the session URL is only visible in the browser address bar. This feature adds a dedicated Invite panel that surfaces the link prominently, provides a one-click copy button, displays a QR code for mobile participants, and shows real-time participant count so the facilitator knows when everyone is in the room.

---

## Goals

1. Add an **Invite panel** accessible from the room header (button or icon) as a modal or slide-in drawer.
2. Display the full **session URL** (copyable text field).
3. Provide a **"Copy link" button** that copies the URL to the clipboard using the `navigator.clipboard` API and shows a brief "Copied!" confirmation.
4. Generate and display a **QR code** of the session URL so participants on mobile can join by scanning without typing the URL.
5. Show a **live participant count** ("N of M joined" or simply "N participants") updated in real time.
6. Show the **list of participants** who have joined (name only) so the facilitator can confirm attendance before starting.
7. The panel is accessible to all participants (not facilitator-only) so anyone can re-share the link.

---

## Non-Goals

- Sending invites by email or messaging platform.
- Setting a participant limit or locking the room.
- Generating a room password or access code.

---

## User Stories

**US-007-A — Facilitator copies the invite link**
> As a facilitator, I want a clearly visible button to copy the session link to my clipboard so I can paste it into Slack or Teams without fumbling with the address bar.

**US-007-B — Facilitator sees who has joined**
> As a facilitator, I want to see a list of participants who have joined so I know when my whole team is in the room and we can start.

**US-007-C — Participant shares via QR code**
> As a facilitator or participant in a co-located meeting, I want to show a QR code on my screen so teammates with phones can scan and join instantly.

**US-007-D — Copy confirmation**
> As a facilitator, after clicking "Copy link" I want brief visual confirmation ("Copied!") so I know the action succeeded without checking my clipboard.

---

## Constraints

- QR code must be generated **client-side** — no external QR API calls — to avoid network dependency and privacy concerns. Use a lightweight client-side library (e.g., `qrcode` npm package, ~14 KB gzipped).
- `navigator.clipboard.writeText` is used for copying; must gracefully fall back to `document.execCommand('copy')` in environments where the Clipboard API is unavailable.
- The "Copied!" state resets after 2 seconds.
- The invite panel (modal/drawer) must trap focus when open (WCAG 2.1 AA modal pattern) and close on Escape key or clicking the backdrop.
- Participant list in the invite panel is read-only and synced from Zustand store (no additional WS messages required).
- QR code size: 200×200 px minimum; must be legible when displayed on a standard laptop screen.
- The invite button in the header must be visible and accessible on both mobile and desktop.

---

## Implementation Notes

- The session URL is: `window.location.origin + '/session/' + sessionId`.
- QR code is rendered as an `<svg>` or `<canvas>` element inside the panel.
- No server changes are required; all state is already available in the Zustand session store.

---

## Success Criteria

- An "Invite" button (icon or labelled) is present in the room header.
- Clicking it opens a panel showing the full session URL, a "Copy link" button, and a QR code.
- Clicking "Copy link" copies the URL to clipboard and shows "Copied!" for 2 seconds.
- The QR code is scannable on a phone and navigates to the correct session URL.
- The panel shows the current participant count and names, updating in real time as participants join or leave.
- The panel closes on Escape key, clicking the backdrop, or a close button.
- Focus is trapped inside the panel while it is open.
- The invite button and panel render correctly on a 375 px mobile viewport.
- All existing tests pass; new tests cover the clipboard copy logic and QR code rendering.
- Coverage thresholds from `specs/TESTING.MD` maintained.
