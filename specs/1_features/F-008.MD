# F-008 — Game Settings & Configuration

## Context

Different teams have different estimation preferences. Some use Fibonacci, others use T-shirt sizes or powers of 2. Some teams want cards auto-revealed when everyone has voted; others prefer the facilitator to stay in control. This feature adds a Settings panel (facilitator-only) that allows deck type and game-behavior options to be configured. Settings take effect immediately and are broadcast to all participants via `SESSION_STATE`.

Settings are session-scoped and in-memory — they are not persisted beyond the session lifetime.

---

## Goals

1. Add a **Settings panel** accessible from the room header (facilitator only) as a modal or slide-in drawer.
2. Allow the facilitator to choose a **deck type** from a preset list; changing the deck broadcasts a new `SESSION_STATE` to all participants.
3. Allow the facilitator to toggle **auto-reveal**: when enabled, cards are revealed automatically the moment every participant has cast a vote.
4. Allow the facilitator to toggle **show average on reveal**: controls whether the numeric average is displayed in the results panel (F-005).
5. Allow the facilitator to set a **voting timer** (optional countdown, 0 = no timer) that auto-reveals when it expires. The timer counts down visibly for all participants.
6. Allow the facilitator to set the **session name** (display name shown in the room header), up to 60 characters.

---

## Non-Goals

- Persistent user preferences across sessions.
- Custom deck creation (arbitrary card values entered by the user) — preset decks only in this feature.
- Per-story timer overrides.
- Exporting settings as a template.

---

## User Stories

**US-008-A — Facilitator changes deck type**
> As a facilitator, I want to switch the deck from Fibonacci to T-shirt sizes (or another preset) so my team can estimate using the scale they prefer.

**US-008-B — Facilitator enables auto-reveal**
> As a facilitator, I want to turn on auto-reveal so that cards flip automatically when everyone has voted, saving me from having to click "Reveal" every round.

**US-008-C — Facilitator sets a voting timer**
> As a facilitator, I want to set a countdown timer (e.g., 60 seconds) per round so that the team doesn't deliberate too long before voting.

**US-008-D — Team sees the countdown**
> As a participant, I want to see the remaining time on the timer so I know when my vote will be auto-submitted or revealed.

**US-008-E — Facilitator renames the session**
> As a facilitator, I want to set a session name (e.g., "Sprint 42 Planning") that appears in the room header so participants know which planning session they're in.

**US-008-F — Participants see deck change in real time**
> As a participant, when the facilitator changes the deck I want to see the new cards appear immediately so I'm always using the right values.

---

## Constraints

- The settings panel is only accessible to the facilitator; participants do not see the settings button.
- Settings changes are applied immediately and broadcast via `SESSION_STATE` — not queued to the next round.
- Changing the deck mid-round clears any votes already cast (a `ROUND_RESET` is issued alongside the deck change); the facilitator must confirm this action in a confirmation prompt.
- Timer value: 0 (disabled) or 15 / 30 / 60 / 90 / 120 seconds. Timer state is managed client-side (countdown runs in the browser); the server holds only the configured duration and the timestamp when the timer started.
- When the timer expires, the server (not the client) triggers the reveal to prevent race conditions from network latency.
- Auto-reveal is processed server-side: the server checks after each `VOTE` whether all connected participants have voted and, if the flag is set, issues `CARDS_REVEALED`.

### Preset Decks

| Deck Name | Values |
|-----------|--------|
| Fibonacci (default) | `1, 2, 3, 5, 8, 13, 21, ?, ☕` |
| Modified Fibonacci | `0, 1, 2, 3, 5, 8, 13, 20, 40, 100, ?, ☕` |
| T-shirt sizes | `XS, S, M, L, XL, ?, ☕` |
| Powers of 2 | `1, 2, 4, 8, 16, 32, 64, ?, ☕` |

T-shirt size values are strings; the `CardValue` type must be extended to `number | string`.

---

## Data Model Extension

```typescript
type CardValue = number | string;  // extended from F-000 (was number | '?' | '☕')

type DeckType = 'fibonacci' | 'modified-fibonacci' | 'tshirt' | 'powers-of-two';

interface SessionSettings {
  deckType: DeckType;
  autoReveal: boolean;
  showAverage: boolean;
  timerSeconds: 0 | 15 | 30 | 60 | 90 | 120;
  sessionName: string;  // 0–60 chars; default: 'Scrum Poker'
}

// Session extended:
interface Session {
  // ... existing fields ...
  settings: SessionSettings;
  timerStartedAt: Date | null;
}
```

---

## New WebSocket Events

### Client → Server
| Event | Payload | Description |
|-------|---------|-------------|
| `UPDATE_SETTINGS` | `Partial<SessionSettings>` | Facilitator updates one or more settings |

Server validates, applies changes, and broadcasts `SESSION_STATE` to all clients. If deck changes, also broadcasts `ROUND_RESET`.

---

## Success Criteria

- A "Settings" button is visible in the room header for the facilitator only.
- Opening settings shows: deck type selector, auto-reveal toggle, show-average toggle, timer selector, and session name field.
- Changing the deck type (with confirmation if votes exist) immediately updates the card deck for all participants.
- Enabling auto-reveal causes the next round to reveal automatically when the last vote is cast.
- Setting a timer displays a countdown for all participants; expiry triggers server-side reveal.
- Changing the session name updates the room header for all participants within one WebSocket round trip.
- T-shirt size deck renders non-numeric string values correctly in the deck, results, and distribution.
- Settings panel is accessible: focusable controls, traps focus when open, closes on Escape.
- All existing tests pass; new tests cover `UPDATE_SETTINGS` handler (server), auto-reveal logic, timer expiry logic, and settings panel rendering (client).
- Coverage thresholds from `specs/TESTING.MD` maintained.
