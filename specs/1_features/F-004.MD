# F-004 — Voting: Cast, Change & Reveal

## Context

This feature delivers the core game mechanic of Scrum Poker: participants select a card to cast their vote, the facilitator reveals all votes simultaneously, and the facilitator resets the round when done. All vote state is managed in real time over WebSocket. Vote values remain hidden from other participants until the facilitator triggers a reveal.

This feature builds on top of the room shell (F-003). The card deck area and facilitator controls rendered in F-003 are populated here.

---

## Goals

1. Render the **card deck** as a row of selectable card components, each showing a value from the session's deck (`[1, 2, 3, 5, 8, 13, 21, '?', '☕']` by default).
2. Allow a participant to **cast a vote** by clicking a card, which highlights the selected card and sends a `VOTE { value }` message to the server.
3. Allow a participant to **change their vote** before reveal by clicking a different card (resends `VOTE` with the new value).
4. Show a **"voted" indicator** on each participant in the list (face-down card icon) without revealing the value to others.
5. Show the **facilitator controls panel** (only visible to the facilitator): a "Reveal cards" button (active once at least one vote has been cast) and a "New round" button.
6. When the facilitator clicks "Reveal cards", send `REVEAL {}` and broadcast `CARDS_REVEALED` to all participants — all cards flip face-up simultaneously.
7. After reveal, **disable further voting** (deck is locked) until the facilitator starts a new round.
8. When the facilitator clicks "New round", send `RESET { story? }` and broadcast `ROUND_RESET` — all votes clear and the deck unlocks.

---

## Non-Goals

- Displaying vote statistics or consensus analysis after reveal (F-005).
- Automatically revealing when all participants have voted (F-008 setting).
- Timer / countdown (F-008 setting).
- Card deck customisation (F-008).

---

## User Stories

**US-004-A — Participant casts a vote**
> As a participant, I want to click a card to cast my vote so my team knows I'm ready, without revealing my value to others.

**US-004-B — Participant changes vote**
> As a participant, before cards are revealed I want to be able to change my vote by clicking a different card so I can reconsider my estimate.

**US-004-C — Facilitator reveals votes**
> As a facilitator, I want to click "Reveal cards" to flip all cards face-up simultaneously so the whole team sees everyone's estimate at the same moment.

**US-004-D — Participant cannot vote after reveal**
> As a participant, after cards are revealed I want the deck to lock so that late votes don't corrupt the revealed results.

**US-004-E — Facilitator resets the round**
> As a facilitator, after discussing the estimates I want to click "New round" to clear all votes and start the next story so the team can estimate again.

**US-004-F — Non-facilitator cannot reveal or reset**
> As a participant (non-facilitator), I should not see or be able to use the Reveal or New round controls so that only the facilitator drives the game flow.

---

## Constraints

- Card click sends `VOTE { value: CardValue }` to the server. The server updates the session and broadcasts `VOTE_CAST { participantId }` to all clients (value is NOT in this broadcast — only the participant ID, so others know someone voted without seeing the value).
- `REVEAL` is only processed server-side if the sender is the facilitator; the server returns `ERROR` otherwise.
- `RESET` is only processed server-side if the sender is the facilitator.
- Cards must be keyboard accessible: focusable, selectable with Enter/Space.
- Selected card must have a distinct visual selected state (not just color — also a border or scale change for accessibility).
- "Reveal cards" button must be disabled when zero votes have been cast.
- After `CARDS_REVEALED`, the full vote map `{ participantId: CardValue }` is sent to all clients — participant names are resolved from session state.
- After `ROUND_RESET`, the Zustand store clears all votes and `revealed` returns to `false`.
- All vote state lives in Zustand; components are purely reactive.

---

## WebSocket Flow

```
Voting phase:
Participant  →  VOTE { value }
Server       →  VOTE_CAST { participantId }  (broadcast to all)

Reveal:
Facilitator  →  REVEAL {}
Server       →  CARDS_REVEALED { votes: Record<participantId, CardValue> }  (broadcast)

Reset:
Facilitator  →  RESET { story? }
Server       →  ROUND_RESET { story }  (broadcast)
```

---

## Success Criteria

- The card deck renders all values from the session deck; each is clickable.
- Clicking a card highlights it as selected and sends `VOTE` to the server.
- Clicking a different card before reveal updates the selection and resends `VOTE`.
- All participants see a "voted" indicator (face-down card) on voters in the participant list — not the vote value.
- Only the facilitator sees "Reveal cards" and "New round" buttons.
- "Reveal cards" is disabled when no votes exist.
- After clicking "Reveal cards", all participants see each card flipped face-up with the voter's name and value.
- After reveal, the deck is locked — clicking cards does nothing.
- After "New round", all votes clear, the deck unlocks, and selected card state resets.
- Non-facilitator `REVEAL` messages are rejected by the server with an `ERROR` response.
- All existing tests pass; new tests cover VOTE, REVEAL, RESET handlers (server) and card selection/reveal rendering (client).
- Coverage thresholds from `specs/TESTING.MD` maintained.
