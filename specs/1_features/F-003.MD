# F-003 — Voting Room Layout

## Context

After a participant joins or a facilitator creates a session (F-001, F-002), they land in the voting room. This feature defines the persistent room shell: the layout, navigation chrome, participant panel, current-story display, and the card deck area. No voting logic is implemented here — that comes in F-004. This feature is purely about the room structure, component hierarchy, and real-time participant presence.

The room must be fully responsive (mobile and desktop) and accessible (WCAG 2.1 AA), as required by `specs/SYSTEM.MD`.

---

## Goals

1. Render the persistent voting room shell once the user is authenticated into a session.
2. Display a **header** with the app name, current session name/story, and a connection status indicator.
3. Display a **participant panel** (sidebar on desktop, collapsible on mobile) listing all current participants with their name, vote status (voted / not voted), and a "facilitator" badge on the session owner.
4. Display the **card deck area** (bottom of screen) as the zone where card components will be rendered (F-004 populates the actual cards).
5. Display the **story/ticket title** prominently as the prompt above the deck.
6. Subscribe to `SESSION_STATE`, `PARTICIPANT_JOINED`, `PARTICIPANT_LEFT`, `VOTE_CAST` events and update the participant list in real time.
7. Show a reconnecting banner when the WebSocket connection drops.

---

## Non-Goals

- Rendering clickable card values (F-004).
- Revealing votes or showing vote values (F-004, F-005).
- Editing the story title in-session (F-006).
- Facilitator controls (reveal, reset buttons) (F-004).
- Invite panel (F-007).
- Settings panel (F-008).

---

## User Stories

**US-003-A — Participant sees the room**
> As a participant, after joining I want to see a clearly structured room with the current story, my teammates, and where I'll vote so I know what's happening.

**US-003-B — Participant sees who's in the room**
> As a participant, I want to see a list of everyone in the session with an indicator showing whether they've voted so I know when the team is ready to reveal.

**US-003-C — Participant sees the facilitator identified**
> As a participant, I want to see which person is the facilitator so I know who's running the session.

**US-003-D — Participant sees real-time presence updates**
> As a participant, when a new teammate joins or leaves I want the participant list to update immediately without a page refresh.

**US-003-E — Participant sees connection status**
> As a participant, if my connection drops I want to see a clear "Reconnecting…" banner so I'm not confused by a frozen UI.

---

## Constraints

- Component hierarchy must be clean and support adding F-004 through F-008 features without major restructuring.
- Participant list updates must be driven by Zustand store state (not local component state) so all room sub-components share the same source of truth.
- Vote status display during voting phase: show a face-down card icon for "voted" and an empty slot for "not voted" — never show the actual vote value before reveal.
- The room must render correctly on screens from 375 px wide (iPhone SE) to 1440 px wide.
- Keyboard navigation: all interactive elements must be focusable and operable via keyboard.
- The facilitator badge must be visible to all participants (not only the facilitator).
- Participant count must be displayed in the panel header.

## Room Layout Sketch

```
┌──────────────────────────────────────────────────────┐
│  Header: "Scrum Poker"   [Story Title]  [● Connected] │
├──────────────────────┬───────────────────────────────┤
│  Participants (N)    │                               │
│  ─────────────────  │      Story / Prompt Area      │
│  👑 Mayank (you)    │                               │
│  ● Alice   [voted]  │  ─────────────────────────── │
│  ○ Bob     [...]    │                               │
│                     │      Card Deck Area           │
│                     │   (cards rendered by F-004)   │
│                     │                               │
└──────────────────────┴───────────────────────────────┘
```

On mobile: participant list collapses to a togglable panel; card deck takes full width.

---

## Success Criteria

- After joining, the room renders with a header, participant sidebar, story display area, and card deck placeholder.
- All current participants are listed with their name and vote status (voted ✓ / waiting …).
- The facilitator has a visible crown/badge icon.
- When a new participant joins, they appear in the list within one WebSocket message round trip.
- When a participant disconnects, they are marked as disconnected (or removed) in real time.
- When the WebSocket drops, a non-blocking "Reconnecting…" banner appears at the top of the screen.
- The layout is usable at 375 px width (mobile) with the participant list toggleable.
- All existing tests pass; new tests cover room rendering and participant list updates.
- Coverage thresholds from `specs/TESTING.MD` maintained.
