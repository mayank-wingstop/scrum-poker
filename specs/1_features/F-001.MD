# F-001 — Session Creation

## Context

Before any estimation can happen, a facilitator must be able to create a new Scrum Poker session. This is the first user-facing feature of the application: the landing page and the session-creation flow. When a session is created, a unique shareable URL is generated. The facilitator is immediately placed in the session as its owner and redirected to the voting room.

This feature delivers the REST endpoint (`POST /sessions`) for session creation, the landing page UI, the in-memory session store logic, and the client-side routing that moves the facilitator into the room.

---

## Goals

1. Allow a facilitator to create a new session from the home page by entering a display name and optionally a first story title.
2. Generate a UUID v4 session ID on the server and return the session URL to the client.
3. Initialize the in-memory session store with the new session (facilitator as first participant, selected deck, empty vote state).
4. Redirect the facilitator to the session room URL (`/session/:sessionId`) immediately after creation.
5. Persist the facilitator's participant ID and session ID in browser `sessionStorage` so the app can restore identity on page refresh.

---

## Non-Goals

- Authentication or user accounts.
- Deck type selection at creation time (deferred to F-008: Game Settings).
- Persistent storage of any session data beyond server memory.
- Session management dashboards or session history.

---

## User Stories

**US-001-A — Facilitator creates a session**
> As a facilitator, I want to open the app and click "Create game" so that a new session is started and I receive a shareable link to invite my team.

**US-001-B — Facilitator sets display name**
> As a facilitator, I want to enter my display name before creating a session so that other participants can identify me in the room.

**US-001-C — Facilitator sets first story**
> As a facilitator, I want to optionally enter the first story or ticket name when creating the session so that participants know what they're voting on immediately.

**US-001-D — Facilitator is placed in the room**
> As a facilitator, after creating the session I want to be automatically placed in the voting room so I don't have to take any extra steps to join my own session.

---

## Constraints

- Session IDs must be UUID v4 (as specified in `specs/ARCHITECTURE.MD`).
- The default deck is Fibonacci: `[1, 2, 3, 5, 8, 13, 21, '?', '☕']`.
- The facilitator's participant ID must also be UUID v4 and stored in `sessionStorage` as `participantId`.
- The session ID must be stored in `sessionStorage` as `sessionId`.
- The `POST /sessions` endpoint must be rate-limited (express-rate-limit already in dependencies).
- Display name must be 1–30 characters; non-empty.
- Story title is optional; max 200 characters if provided.
- All constraints in `specs/SYSTEM.MD` apply (no PII, no persistence, session isolation).

---

## API Contract

### `POST /sessions`

**Request body:**
```json
{
  "facilitatorName": "string (1–30 chars, required)",
  "story": "string (0–200 chars, optional)"
}
```

**Response `201 Created`:**
```json
{
  "sessionId": "uuid-v4",
  "participantId": "uuid-v4",
  "sessionUrl": "/session/:sessionId"
}
```

**Error `400`:** Missing or invalid `facilitatorName`.

---

## Success Criteria

- Visiting `http://localhost:5173` shows a landing page with an app logo/title, a display name input, an optional story input, and a "Create game" button.
- Submitting the form with a valid name calls `POST /sessions` and receives a 201 with a valid UUID session ID.
- The browser is redirected to `/session/:sessionId` after successful creation.
- `sessionStorage.participantId` and `sessionStorage.sessionId` are set.
- The facilitator appears in the session's participant list server-side.
- Submitting with an empty display name shows a validation error and does not call the API.
- The "Create game" button is disabled while the API call is in flight.
- All existing tests continue to pass; new unit tests cover the `POST /sessions` handler and the `CreateSession` component.
- Coverage thresholds from `specs/TESTING.MD` are maintained.
