## 1. User Flows

### UF-001-A — Happy Path: Create a Session

```
1. User navigates to http://localhost:5173/ (root route "/")
2. Landing page renders:
   - App logo + name ("Scrum Poker") centered at top
   - Tagline: "Estimate together. Reveal at once."
   - Form card with:
       a. "Your display name" text input (required, autofocused)
       b. "First story title" text input (optional, placeholder: "e.g. US-101 Login page")
       c. "Create game" primary button
3. User types display name (e.g. "Alice")
4. User optionally types a story title
5. User clicks "Create game" or presses Enter
6. Client validates:
   - name.length >= 1 AND name.length <= 30  →  proceed
7. Button enters loading state (disabled + spinner label "Creating…")
8. Client calls POST /sessions with { facilitatorName, story }
9. Server responds 201 { sessionId, participantId, sessionUrl }
10. Client writes to sessionStorage:
    - sessionStorage.setItem("sessionId", sessionId)
    - sessionStorage.setItem("participantId", participantId)
11. Client navigates to /session/:sessionId (React Router)
12. Facilitator arrives in voting room (F-003 scope)
```

### UF-001-B — Validation Error: Empty Display Name

```
1–4. Same as UF-001-A
5. User clicks "Create game" with empty name field
6. Client validates: name is empty → do NOT call API
7. Error message appears inline below the name input:
   "Display name is required."
8. Name input receives focus and error border styling
9. Button remains enabled (not in loading state)
10. User corrects name → error clears on next keystroke (or on blur if valid)
```

### UF-001-C — Validation Error: Name Too Long

```
1–4. Same as UF-001-A
5. User has typed 31+ characters in name field
   (Input enforces maxlength="30" natively — characters beyond 30 are blocked)
   OR user pastes text that truncates to 30 chars automatically
6. No server call is made for > 30 char names (natively prevented)
```

### UF-001-D — API Error State

```
1–7. Same as UF-001-A (button enters loading state)
8. POST /sessions returns 4xx/5xx or network timeout
9. Button returns to enabled state with original label "Create game"
10. Error banner appears above the form:
    "Something went wrong. Please try again." (with dismiss ×)
11. Name and story inputs retain their values
```

### D-102 — Typography

| Role | Font Stack | Size | Weight | Line Height | Usage |

## 4. Interaction Behavior Guidelines

### IB-001 — Autofocus on Load

The display name input receives `autoFocus` on component mount. This allows keyboard users and power users to immediately start typing without clicking.

**Constraint:** On mobile, suppress autofocus (it triggers the virtual keyboard immediately on load). Detect mobile with `window.matchMedia('(pointer: coarse)')` and skip autofocus if true.

### IB-002 — Real-time Validation

Validation is **on submit only** (not on blur or keystroke). This avoids premature error states while the user is still typing. After first submit attempt, errors update reactively on keystroke to provide immediate correction feedback.

**Sequence:**
1. User has NOT submitted yet → no errors shown regardless of current input value.
2. User submits with empty name → error message appears below name input.
3. User starts typing → error message disappears as soon as `name.length >= 1`.

### IB-003 — Button Loading State

When form is submitted with valid data:
1. Disable the button immediately (prevent double-submit).
2. Replace button label with "Creating…" and show an inline spinner (16px animated SVG or CSS spinner) to the left of the text.
3. Restore button to original state on any error response.

The spinner animation: `animation: spin 1s linear infinite` using a partial border circle (CSS `border-top-color: transparent`).

### IB-004 — Error Banner Dismiss

The API error banner (shown on 4xx/5xx):
- Appears above the form fields, inside the card.
- Has a close (×) button on the right.
- Dismisses automatically after 8 seconds OR when user closes manually.
- Re-shows if user re-submits and gets another error.

### IB-005 — Character Limit Feedback

- Display name input has `maxlength="30"`.
- No character counter displayed (YAGNI for this screen).
- Native browser behavior blocks input beyond 30 characters.

### IB-006 — Form Submission via Enter Key

Pressing Enter in either input field submits the form (standard HTML form behavior). The `<form>` element wraps both inputs and the button; `type="submit"` on the button handles this natively.

## 5. Accessibility and Readability Criteria

### AC-001 — Color Contrast

| Element | Foreground | Background | Ratio | WCAG AA |
|---------|-----------|-----------|-------|---------|
| Body text | `#0F172A` | `#FFFFFF` | 19.1:1 | ✅ Pass |
| Secondary text | `#64748B` | `#FFFFFF` | 5.91:1 | ✅ Pass |
| Button label | `#FFFFFF` | `#4F46E5` | 4.54:1 | ✅ Pass (≥ 4.5:1) |
| Placeholder text | `#94A3B8` | `#FFFFFF` | 3.11:1 | ⚠️ Placeholder — WCAG 1.4.3 exempts placeholder text; acceptable |
| Error message text | `#EF4444` | `#FFFFFF` | 3.99:1 | ⚠️ Below 4.5:1 — pair with icon ⚠️ to compensate |
| Disabled button text | `#FFFFFF` | `#A5B4FC` | 2.08:1 | ✅ Exempt (disabled state is WCAG-exempt) |

**Mitigation for error text:** Error messages must include a warning icon (⚠️ or SVG equivalent) before the text so the error is not communicated by color alone. This satisfies WCAG 1.4.1 (Use of Color).

### AC-002 — Keyboard Navigation

Tab order (top to bottom):
1. Display name input
2. Story title input
3. "Create game" button

All elements reachable via Tab; Shift+Tab reverses. No tab traps on the landing page. Focus never disappears.

### AC-004 — Focus Ring

All interactive elements must display a visible focus ring:
- `outline: 3px solid rgba(79, 70, 229, 0.5)`
- `outline-offset: 2px`
- Do NOT use `outline: none` without a custom replacement.

### AC-005 — Zoom and Reflow

- Page must be fully usable at 400% browser zoom (WCAG 1.4.10 Reflow).
- No horizontal scrollbar at 400% on a 1280px viewport.
- All text must reflow; no text truncation or overflow hidden on key content.

## 6. Edge Cases

### EC-001 — Long Display Name (at boundary)

Input: 30 characters (max allowed). Expected: Form submits without error. Name is passed as-is to the API.

### EC-002 — Story Title at Maximum Length

Input: 200 characters in story field. Expected: Form submits; API receives the full 200-char string. No truncation client-side (maxlength="200").

### EC-003 — Whitespace-Only Name

Input: "   " (spaces only). Expected: Client trims the value before validation; trimmed string is empty → same error as empty name ("Display name is required."). Do NOT call API with whitespace-only names.

### EC-004 — Very Narrow Viewport (320px)

Expected: Card stacks to full viewport width. Text remains readable. Button remains tappable (min 44px tall). No horizontal overflow. Logo/title wraps gracefully.

### EC-005 — Slow Network (API Takes > 3 Seconds)

Expected: Button stays disabled the entire duration. No timeout on the client — wait until the server responds or the connection closes. No duplicate API calls (button is disabled).

### EC-006 — API Returns 400 (Invalid Name — Server-Side Rejection)

Scenario: Client validation passes but server rejects with 400 (e.g., name has control characters).
Expected: Error banner appears with generic "Something went wrong. Please try again." message. Do not expose raw server error messages to the user.

### EC-007 — Session Storage Unavailable (Private Browsing)

In some browsers, `sessionStorage` may throw in strict private mode. Expected: App catches the exception and still navigates to `/session/:sessionId`. The user will need to re-enter their name if they refresh — acceptable degradation.
