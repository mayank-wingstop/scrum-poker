## Non-Blocking Suggestions

### S-001 — `dist/` and `coverage/` directories are not gitignored at the workspace level

**Severity:** SUGGESTION
**Files:** `src/client/dist/`, `src/server/dist/`, `src/client/coverage/`, `src/server/coverage/`

The root `.gitignore` correctly excludes `dist/` and `coverage/` globally, so these won't be committed as long as git respects the root ignore file. However, the `dist/` directories were generated by `npm run build` during the coding stage and are present on disk. Confirm these paths are being picked up by the root `.gitignore` before the first `git push`. A quick `git status` check is sufficient.

**Recommendation:** Run `git status` before pushing and confirm no `dist/` or `coverage/` files appear as untracked. No code change required.

---

### S-002 — `moduleResolution: "bundler"` in base tsconfig may surprise server-workspace tooling in future

**Severity:** SUGGESTION
**File:** `tsconfig.base.json`

The base tsconfig sets `moduleResolution: "bundler"`, which is correct for the Vite client. Both the server and shared workspaces correctly override this with `"node"` in their own tsconfigs. This is working correctly now, but is a subtle footgun if a future developer adds a new workspace and forgets the override. Worth a brief comment in `tsconfig.base.json` to make the intent explicit.

**Recommendation:** Add a comment to `tsconfig.base.json`:
```json
// Note: server and shared workspaces override moduleResolution to "node"
// "moduleResolution": "bundler" — client-facing default; override per workspace as needed
```
No functional change required.
