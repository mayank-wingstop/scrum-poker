# Test Plan — F-001: Session Creation

**Feature:** F-001 — Session Creation
**Stage:** 5 — Test Plan
**Planner:** tadf-tester

---

## Objective and Scope

Validate that the Session Creation feature — landing page UI, `POST /sessions` REST endpoint, client-side form behaviour, React Router integration, and design token rendering — conforms to all approved specifications in `specs/1_features/F-001.MD`, `specs/2_design/F-001.MD`, and `specs/3_architecture/F-001.MD`.

**In scope:** Landing page rendering, form validation, API contract, session store state, sessionStorage persistence, navigation, design tokens (colors, typography, spacing, shadows), ARIA attributes, loading state, error banner.

**Out of scope:** Voting room UI (F-002/F-003), WebSocket session join (F-002), deck configuration (F-008).

## Test Scenarios

### S-01 — Happy path: create session, receive 201, navigate
**Type:** Automated (server + client)
**Criteria:** POST /sessions with valid name returns 201; body contains UUID v4 sessionId, UUID v4 participantId, sessionUrl matching `/session/:id`; client navigates to `/session/:id`; sessionStorage.sessionId and sessionStorage.participantId are set.
**Pass condition:** All assertions green.

### S-02 — Session stored with facilitator as first participant
**Type:** Automated (server)
**Criteria:** After POST /sessions, `sessionStore.get(sessionId)` returns a Session; `session.facilitatorId === participantId`; participant entry has `vote: null`, `connected: false`; `session.deck` equals Fibonacci default.
**Pass condition:** All assertions green.

### S-03 — sessionStorage write failure is swallowed (EC-007)
**Type:** Automated (client)
**Criteria:** When `sessionStorage.setItem` throws, the component still calls `navigate('/session/:id')`.
**Pass condition:** Navigation mock called despite storage error.

### S-04 — Empty display name shows inline error, no API call
**Type:** Automated (client)
**Criteria:** Submit with empty name; `aria-invalid="true"` on input; error text "Display name is required." appears; fetch not called.
**Pass condition:** All assertions green.

### S-05 — Error clears reactively after first failed submit
**Type:** Automated (client)
**Criteria:** After failed submit shows error, typing one character clears the error.
**Pass condition:** Error message absent after first keystroke.

### S-06 — Whitespace-only name blocked (EC-003)
**Type:** Automated (client)
**Criteria:** Input "   " (spaces only); submit; error appears; fetch not called.
**Pass condition:** Error shown; zero API calls.

### S-07 — First story title stored in session
**Type:** Automated (server)
**Criteria:** POST /sessions with `{ facilitatorName: "Alice", story: "US-101" }`; `session.currentStory === "US-101"`.
**Pass condition:** Assertion green.

### S-08 — Autofocus applied on desktop (IB-001)
**Type:** Visual (screenshot evidence)
**Criteria:** On page load in a non-touch browser, the display name input is focused (cursor visible or focus ring present).
**Pass condition:** Screenshot shows focus indicator on name input.

### S-09 — Button loading state during submission (IB-003)
**Type:** Automated (client)
**Criteria:** On submit with valid name (fetch never resolves), button text changes to "Creating…" and button is `disabled`; `aria-busy="true"` set.
**Pass condition:** Disabled button with "Creating…" label found in DOM.

### S-10 — API error banner appears and is dismissible (IB-004)
**Type:** Automated (client)
**Criteria:** Fetch returns 500; banner shows "Something went wrong. Please try again."; clicking × removes the banner; button re-enabled.
**Pass condition:** Banner present then absent after dismiss click.

### S-11 — Color tokens rendered correctly (D-101)
**Type:** CSS extraction + Visual
**Criteria:** All 16 CSS custom property values extracted from `dist/assets/*.css` match values specified in D-101.
**Pass condition:** All 16 tokens present with correct hex values; no browser-default colors visible.

### S-12 — Typography rendered correctly (D-102)
**Type:** CSS extraction + Visual
**Criteria:** `font-family` on body includes `Inter`; `h1` on landing page is `2rem/700`; labels are `1rem/600`; error messages are `0.875rem`.
**Pass condition:** Observed values match spec; screenshot confirms Inter renders.

### S-13 — Spacing and hit targets meet spec (D-103)
**Type:** Visual
**Criteria:** Form card has ≥ 32px internal padding; button has min-height ≥ 44px; field gap ≥ 16px between name and story inputs.
**Pass condition:** Screenshot evidence; measurements consistent with spec.

### S-14 — Form card has medium elevation shadow (D-104)
**Type:** CSS extraction + Visual
**Criteria:** `--shadow-md` token present in CSS with exact value from D-104; card visually elevated above canvas in screenshot.
**Pass condition:** Token value matches spec; card shadow visible in screenshot.

### S-15 — Primary button default and disabled states (D-105)
**Type:** Visual
**Criteria:** Default state: background `#4F46E5`; disabled/loading state: background `#A5B4FC`, opacity 0.7, cursor `not-allowed`.
**Pass condition:** Screenshot shows correct button colors; CSS confirms token values.

### S-16 — Text input default and error states (D-106)
**Type:** Visual
**Criteria:** Default border `1px solid #E2E8F0`; error state border `2px solid #EF4444` visible alongside error message text.
**Pass condition:** Screenshots of both states confirm visual differentiation.

### S-17 — Rate limiter active in production config
**Type:** Code inspection + unit test bypass verification
**Criteria:** `index.ts` registers rate limiter before sessions router; `skip` function returns `true` when `NODE_ENV === test` (confirmed by tests passing past 10 requests); in production `skip` returns `false`.
**Pass condition:** Code inspection confirms; tests pass without 429 errors.
